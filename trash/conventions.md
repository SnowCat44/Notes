# 작성 규칙 (Conventions)

이 문서는 학술 노트의 **출처(reference)** 와 **최종 수정일(last updated)** 표기 규칙을 정의한다. 모든 항목은 이 규칙을 따른다. (이 문서는 저장소 관리용이며 사이트 사이드바에는 노출하지 않는다.)

---

## 1. 기본 원칙

- **엄밀성 우선**: 사실 주장에는 반드시 출처를 붙인다. 출처 없는 주장은 "직접 작성/추론"임을 명시한다.
- **날짜 형식은 ISO 8601로 통일**: `YYYY-MM-DD` (예: `2026-09-21`). 다른 형식(2026.09.21, 2026년 9월 21일 등)은 쓰지 않는다.
- **두 층위로 관리**: 페이지 전체에 포괄적으로 붙이는 표기와, 개별 문장에 붙이는 표기를 구분한다.

---

## 2. 최종 수정일 표기

최종 수정일은 **수동으로 관리**한다. Git 자동 기록에 의존하지 않는다.

### 2-1. 페이지 단위 (상단)

각 페이지 **제목 바로 아래**에 페이지 전체의 최종 수정일을 둔다. 페이지 내용을 고칠 때마다 이 날짜를 갱신한다.

```markdown
# 용어명 (English Term)

*최종 수정일: 2026-09-21*
```

### 2-2. 문장 단위 (각주 안)

특정 문장·주장만 다른 날짜에 갱신·검증했다면, 그 정보를 **해당 문장의 각주 안**에 적는다. (아래 3-2 참고) 페이지 상단 날짜는 "페이지에서 가장 최근에 손댄 날"을 의미하고, 문장 각주의 날짜는 "그 주장을 확인한 날"을 의미한다.

### 2-3. 언제 어느 것을 쓰나

- 페이지를 통째로 훑어보고 손봤다 → **상단 날짜만** 갱신
- 특정 문장 하나의 근거를 새로 확인·교체했다 → 그 **문장 각주에 검증일**을 적고, 상단 날짜도 갱신
- 사실 관계가 민감하거나 시간에 따라 변하는 주장(표준 버전, 권고값 등) → **문장 단위 표기를 권장**

---

## 3. 출처 표기 — 각주(footnote) 방식

문장 단위 출처는 **각주**로 단다. 문장 끝에 `[^식별자]`를 붙이고, 페이지 하단 "출처" 절에 내용을 적는다.

### 3-1. 각주 필드 (필수 / 선택)

| 필드 | 필수 여부 | 비고 |
|---|---|---|
| 제목/문서명 | 필수 | |
| 저자/발행기관 | 권장 | 기관 표준 등은 발행기관 |
| URL 또는 DOI | 자료에 있으면 필수 | DOI 우선 |
| 발행일 | 권장 | `YYYY-MM-DD` 또는 연도 |
| **접근일(accessed)** | **웹·URL 출처는 필수** | 그 외 선택. 웹 내용은 변할 수 있으므로 확인한 날을 남긴다 |
| 페이지/절 | 선택 | 책·긴 문서에서 위치 특정 시 |
| 로컬 PDF 링크 | 선택 | 저장소에 사본을 둔 경우 |

### 3-2. 출처 유형별 각주 형식

**(a) 웹 / DOI 자료** — 접근일 필수

```markdown
어떤 사실을 주장한다.[^fips204]

[^fips204]: NIST, *FIPS 204: Module-Lattice-Based Digital Signature Standard*, 2024. DOI: <https://doi.org/10.6028/NIST.FIPS.204> (accessed 2026-09-21).
```

**(b) 로컬 PDF (저장소 보관본)**

```markdown
어떤 사실을 주장한다.[^localpaper]

[^localpaper]: 저자명, *문서 제목*, 발행일. 로컬 사본: [refs/example-paper.pdf](../refs/example-paper.pdf), §3.2.
```

**(c) 책 / 논문 (오프라인)**

```markdown
어떤 정의를 인용한다.[^fraleigh]

[^fraleigh]: J. B. Fraleigh, *A First Course in Abstract Algebra*, 7th ed., Addison-Wesley, 2003, p. 195.
```

**(d) 직접 작성·추론한 내용 (출처 없음)** — 반드시 명시

```markdown
아래 의사코드는 개념 설명용으로 직접 작성한 예시이다.[^own]

[^own]: 직접 작성 (2026-09-21). 특정 문헌을 그대로 옮긴 것이 아님.
```

### 3-3. 각주 식별자 규칙

- 영문 소문자 + 숫자, 의미가 드러나게: `[^fips204]`, `[^fraleigh]`, `[^rfc8446]`
- `[^1]`, `[^2]` 같은 순번은 항목이 길어지면 관리가 어려우니 지양한다.

---

## 4. 페이지 하단 — 전체 출처 목록

페이지 맨 아래에 그 페이지에서 인용한 출처를 **포괄적으로 한 번 더 정리**한다. 각주가 본문 흐름 속 세밀한 표기라면, 이 목록은 페이지 전체의 참고문헌 역할을 한다.

```markdown
## 출처 (References)

- NIST, *FIPS 204*, 2024. <https://doi.org/10.6028/NIST.FIPS.204> (accessed 2026-09-21).
- J. B. Fraleigh, *A First Course in Abstract Algebra*, 7th ed., 2003.
```

각주가 실제 참조 지점을 표시하고, 이 하단 목록이 페이지 차원의 출처 대장을 이룬다. 각주를 쓴 경우 MkDocs가 자동으로 각주 목록도 페이지 하단에 렌더링하므로, 이 "출처" 절은 **각주로 달지 않은 일반 참고자료**나 **포괄적 근거**를 정리하는 용도로도 쓴다.

---

## 5. 페이지 뼈대 요약

규칙을 모두 반영한 최소 뼈대는 다음과 같다. (채워 쓸 수 있는 전체 템플릿은 `docs/refs/index.md`의 "항목 템플릿" 참고)

```markdown
# 용어명 (English Term)

*최종 수정일: 2026-09-21*

<p class="definition">한 줄 정의.</p>

## 개요

본문에서 사실을 주장하고 출처를 각주로 단다.[^ref1]
시간에 따라 변하는 값은 문장 각주에 검증일을 남긴다.[^ref2]

## 출처 (References)

- (포괄적 참고문헌 목록)

[^ref1]: 출처 상세. (accessed 2026-09-21)
[^ref2]: 출처 상세. 확인일 2026-09-21.
```
